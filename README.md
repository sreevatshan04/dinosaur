# DINO RUNNER (C + Raylib, Windows 11)

echo "# dinosaur"

A desktop Chrome-style Dinosaur Runner. All graphics and all sounds are generated by code,
so there are **no asset files** to download or lose.

## Controls
| Key | Action |
|---|---|
| SPACE / UP / W | Jump (hold = higher jump) |
| DOWN / S | Duck (in the air: fast fall) |
| P or ESC | Pause / resume (ESC = pause while playing) |
| M | Sound on / off |
| F, F11, Alt+Enter | Fullscreen |
| ESC (menu) | Quit |

Best score and settings are saved in `dino_save.dat` next to `DinoRunner.exe`.

## Setup on Windows 11 (do these in order)

**Which window?** Press the Windows key, type `PowerShell`, press Enter. Every command marked
**[PowerShell]** goes there. Lines marked **[CMD]** go in "Command Prompt" (or just double-click the .bat file).

### Step 1 - Is GCC installed?  [PowerShell]
```powershell
gcc --version
```
If you see a version number, skip to Step 3. If you see "not recognized", continue.

### Step 2 - Install GCC (MinGW-w64)  [PowerShell]
```powershell
winget search winlibs
winget install --id BrechtSanders.WinLibs.POSIX.UCRT -e
```
Close PowerShell, open a **new** one, and run `gcc --version` again.
If `winget` fails or the id is not listed, download a "w64devkit" release (zip) from
https://github.com/skeeto/w64devkit/releases, unzip it to `C:\w64devkit`, then add it to PATH:
```powershell
$old = [Environment]::GetEnvironmentVariable("Path","User")
[Environment]::SetEnvironmentVariable("Path", "$old;C:\w64devkit\bin", "User")
```
(Close and reopen PowerShell afterwards. The PATH is the list of folders Windows searches for programs.)

### Step 3 - Is Raylib installed?  [PowerShell]
```powershell
Test-Path "C:\raylib\raylib-5.5_win64_mingw-w64\include\raylib.h"
```
`True` = installed, skip to Step 5. `False` = continue.

### Step 4 - Install Raylib  [PowerShell]
```powershell
New-Item -ItemType Directory -Force C:\raylib | Out-Null
Invoke-WebRequest -Uri "https://github.com/raysan5/raylib/releases/download/5.5/raylib-5.5_win64_mingw-w64.zip" -OutFile "C:\raylib\raylib.zip"
Expand-Archive -Path "C:\raylib\raylib.zip" -DestinationPath "C:\raylib" -Force
Test-Path "C:\raylib\raylib-5.5_win64_mingw-w64\include\raylib.h"
```
The last line should print `True`. If the download fails, open https://github.com/raysan5/raylib/releases
in a browser, download the file ending in `win64_mingw-w64.zip`, and unzip it into `C:\raylib`.
If your folder name differs, tell the build about it (Step 5).

### Step 5 - Open the project in VS Code  [PowerShell]
```powershell
cd C:\path\to\DinoRunner
code .
```
Install the **C/C++** extension (Microsoft) when VS Code suggests it.
If Raylib is not in the default folder, either edit the `RAYLIB_DIR` line at the top of `compile.bat`,
or set it once (then reopen terminals):
```powershell
[Environment]::SetEnvironmentVariable("RAYLIB_DIR", "D:\your\raylib\folder", "User")
```

### Step 6 - Compile and play
In VS Code press **Ctrl+Shift+B** (runs `compile.bat`), or in File Explorer double-click `compile.bat`.
Then double-click `run.bat`.

The exact command inside `compile.bat` is:
```
gcc src\main.c -o build\DinoRunner.exe -std=gnu11 -O2 -Wall -Wextra ^
    -I"C:\raylib\raylib-5.5_win64_mingw-w64\include" -L"C:\raylib\raylib-5.5_win64_mingw-w64\lib" ^
    -lraylib -lopengl32 -lgdi32 -lwinmm -static -mwindows
```
* `-I` = where `raylib.h` is. `-L` = where `libraylib.a` is. `-lraylib -lopengl32 -lgdi32 -lwinmm` = libraries to link.
* `-static` bakes the GCC runtime into the .exe, and Raylib is linked statically, so **no extra DLLs
  are needed**. Windows' own system DLLs (opengl32, gdi32, ...) are always present.
* `-mwindows` hides the black console window.

## Troubleshooting
* `'gcc' is not recognized` -> redo Step 2 and open a NEW terminal.
* `raylib.h: No such file` -> RAYLIB_DIR is wrong (Step 5).
* `undefined reference to ...` -> the Raylib zip must be the **mingw-w64** one, not the MSVC one.
* No sound -> check Windows output device; the game runs silently without one.
* Windows SmartScreen warning on first run of your own build -> "More info" -> "Run anyway".

## How this project was tested (honest disclosure)
The development environment was **Linux without Raylib or MinGW**, so the game was **NOT compiled
against real Raylib or run on Windows**. What WAS done: `main.c` was compiled with `gcc -Wall -Wextra
-Wpedantic` (no warnings in game code) against a hand-written stand-in for the Raylib functions it uses,
with AddressSanitizer + UBSan, and played for 120,000 frames (~33 min of game time) by a bot that
jumps/ducks, pauses, mutes, dies, restarts and saves. That checks logic, memory use, physics, scoring,
collision, restart and saving. It does **not** check real rendering, real audio, or Raylib API mismatches.
First-run checklist on your PC: window opens -> menu animates -> SPACE starts -> jump/duck work ->
hit a cactus -> GAME OVER -> SPACE restarts -> close and reopen: best score is still there.
If the compiler reports a Raylib-related error, copy the message to me and I will fix it.
